먼저 예제인 [CampUs](https://camp-us.co.kr/) 에서는 Splash Page 후에 메인 페이지에 네비게이트 되는 구조로 되어 있기에, 메인페이지를 기준으로 진단한 정보를 토대로 다룰 예정이다.

![](https://velog.velcdn.com/images/buddle6091/post/f2501bb0-4fae-4e26-a5d3-bdb0113ccadd/image.png)

처음 렌더링 되면 이런 페이지가 나오게 되는데, 일부분만 보여져서 그렇지 이미지를 많이 사용한 페이지이다.

그럼 해당 페이지를 **LightHouse** 는 어떻게 판단했는지 봐보도록 하자.

해당 이미지를 계속 사용하게 된다면 로딩도 느려질 뿐더러, 큰 용량으로 이루어져있는 이미지를 로드하는데 데이터도 많이 든다는 것이다.


## 이미지파일 Webp 확장자로 변환

우선 api로 받는 이미지가 아닌, 직접 이미지를 import 하여서 그린 컴포넌트의 로딩 기간을 단축시키는 방법이 있다. 

기존 이미지 파일인 jpg, png 등은 용량이 상대적으로 크기 때문에 용량을 줄이게 된다면 렌더링 시간을 단축시켜 퍼포먼스 적으로 우수한 모습을 보이는데 도움을 줄 수 있다. 바로 Webp 형식으로 변환하여 사용하면 된다!

### webp란

구글에서 만든 이미지 포맷으로 **Web** 에서만 상용가능한 파일 형식이다.
최대의 장점은 이미지 포맷 (GIF, PNG, JPEG)을 모두 아우르며, 손실 압축 (JPEG) 포맷보다 30% 작은 용량으로, 비손실 압출 포맷 (PNG, GIF) 보다 20 ~ 30% 작은 용량의 파일로 형성이 가능하다.

다만 해당 확장자를 지원하지 않는 브라우저, 기기 등의 환경이 몇 존재한다는 단점이 있긴하다.


### ConvertIo

이번엔 이미지 형식을 webp로 변환해보자.
[ConvertIo](https://convertio.co/kr/jpg-webp/) 라는 사이트가 있는데 들어가보면 쉽게 알아볼 수 있다.
그래서 일단 내가 변환을 해오긴 했다. 아래 사진을 참고하길 바란다.

![](https://velog.velcdn.com/images/buddle6091/post/3bc4dd28-d8e1-476f-b2dd-a27eb7684e1f/image.png)


image1.jpg를 위의 [ConvertIo](https://convertio.co/kr/jpg-webp/) 에서 변환한 것이 바로 아래의 image1.webp 이다.

그리고 파일의 우측을 보면 **340kb** 이였던 파일이 **90.1kb** 까지 줄어진 것을 확인할 수 있다.

import 하는 이미지는 이런 형식으로 크기를 대폭 줄일 수가 있다.

위의 사진은 메인페이지를 이루고 있는 Carousel Slider 중 jpg 파일을 import 해서 작성한 코드의 일부분이다.

원래는 jpg 의 형식이였으나, 위에서 언급했던 webp로 전환하여 다시 LightHouse를 통해 검사해보았다.

![](https://velog.velcdn.com/images/buddle6091/post/ead341df-9119-45da-802c-30edbc79e509/image.png)

성능이 조금이나마 좋아졌다는 것을 확인할 수 있다.. (물론 52 -> 57 이지만..)
조금 오른 이유는 이러하다. 현재 이미지 파일들의 9할 이상이 api에서 따온 url 주소라서 직접적으로 관여할 수 없기에, 그나마 변형 가능한 이미지들만 처리했기에 그렇다.

어쨋든 성능 최적화의 'ㅅ' 만큼은 했다는 것에 의의를 두려고한다.

다음 포스트에서는 api로 부터 받아온 이미지 URL을 클라이언트 서버로 돌릴 때 용량 감소 처리할 수 있는 방법을 알아본 뒤에 다뤄볼까 한다.
