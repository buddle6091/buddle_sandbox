#### ❓ JavaScript의 자료형과 JavaScript만의 특성은 무엇일까?
```
💡	JavaScript에서 데이터의 값은 항상 특정 형태에 속하게 되는데 그것을 자료형이라고 한다.
   그리고 비록 우리 모두 '1'이 숫자라는 것을 알고있지만, JavaScript에서는 그렇지 않을 수도 있다.
   이 부분에서 변수에 저장되는 값의 타입은 어떻게 선언하는지에 따라 언제든지 바꿀 수 있기 때문에 
   JavaScript는 '동적 타입 언어(dynamically typed)'라는 특성을 지닌다.
```

```
자료형, 즉 타입은 기본적으로 총 8가지가 있는데, 먼저 흔히 알고 있는 숫자와 문자가 대표적인 타입이다. 
```
##### - 문자형(String)
```javascript
let str = "My";
let str2 = 'First Dev Blog';
let result = `Dynamic ${str} + ${str2}`;
```
```
문자(char)나 문자열(string)의 값을 받았을 때 사용되는 문자형이다. 
"", '' 구분은 Javascript에서 특정하게 짓진 않으며, 대신 ``(백틱) 기호를 사용하면 
안의 원하는 변수나 표현식을 ${...}을 통해 넣는게 가능하다.
```

##### - 숫자형(Number)
```javascript
let n = 5;
n = 123.4 // 재할당 (8진수)
let c = "5" // 숫자 x, 문자 5
```
```
숫자의 값을 받았을 떄 사용되는 자료형을 숫자형이라 하고, 정수 및 부동소수점의 숫자 뿐만 아니라 연산도 가능하다. 
다만 5 와 "5"는 다르다. 
위에서 나왔듯이 따옴표안의 문자들은 모두 문자형이며, 숫자 또한 이를 빗겨나갈 순 없다. 
만약 숫자 연산에 문자가 들어가게 된다면, NaN 이라는 에러값을 반환받게 될 것이다.
```

##### - Boolean형(Boolean)
```javascript
const isFold = true;
const isactive = false;
```
```
'참'(ture), '거짓'(false)의 값을 나타내는 자료형이다. 
우리는 이 타입을 이용하여 논리 연산자 및 삼항 연산자를 통해 코드를 더 깔끔하게 짤 수 있다.
```

##### - Undefined / null
```javascript
const a;
const b = null;
console.log(a); // 'undefined'
console.log(b); // 'null'
```
```
값이 할당되지 않은 상태'를 나타낼 때 사용되는 타입.
변수는 선언했지만, 값을 할당하지 않았을때 해당 변수에 undefined가 자동으로 할당된다.
undefined를 직접 할당이 가능하지만, 변수가 비어있는 상태를 만들고 싶다면 'null'을 사용하여
undefined가 값이 할당되지 않은 변수의 초기값에 사용되게 하는 것이 좋다고 한다.
이와 같이 undefined와 null은 독린 자료형이라고 한다.
```

##### - 객체형(Object)
```
다양한 키들의 집합과 그 보다 더 복잡한 구조를 저장하는 데 사용된다.

```

```
객체의 고유한 식별자를 만들 때 사용된다.
```

#### ❓ JavaScript 객체와 불변성이란?
```javascript
let object = {
  key1 : value1,
  key2 : value2
}
```
```
위와 같이 객체는 다양한 키들의 집합과 그 보다 더 복잡한 구조를 저장하는 데 사용된다. 
그렇다면 불변객체는 무엇이고 왜 필요할까. 

예를 들어 위의 객체를 복사해주는 함수를 아래와 같이 만들었다. 
```
```javascript
const function1 = function(object, newKey) {
  let newObjcet = object;
  newObject.key = newKey;
  return newObject;
}
```
```
우리는 key1값을 변경시키기 위해 그 함수의 파라미터인 newKey를 각각 넣어, 
key1 의 값이 newKey에 무언가를 넣을 때마다, 그 x값이 나오게 설정했다 치자. 
과연 이 함수로 만들어진 객체는 서로 다른 newKey를 가지고 있을까? 정답은 X.
결국엔 모두 같은 value1을 반환할 것이다. 
위의 함수는 같은 객체를 가리키는 새로운 변수만을 생성하고, 그 변수가 가리키는 구소 공간 값만
변경을 하였기에 항상 같은 객체의 값인 value1을 반환하는 것이다.

위의 함수처럼 객체를 생성한다면, 원하지 않은 객체의 값마저 변경되버리는 사태를 막기위하여 불변객체가 필요하다. 
문제는 모든 변수가 같은 주소공간을 가리키기 때문이라, 
해결방법은 원본 객체 내부의 값들을 복사한 다음 새로운 객체로 만들어 변수에 할당해줘야 한다.
```
```javascript
const function1 = function(object, newKey) {
  return {
    key1 : newKey,
    key2 : object.key2
  }
}
```
```
이러면 newKey가 넣은 값이 key1에 값이 된다.
JavaScript에서는 외부에서 변경이 불가능하게 하는 기능이 없어 
객체의 가변을 막기 위해서는 약속을 만들어 지키도록 해야된다. -> 라이브러리를 통해 가능하기는 함
```

#### 기본형 데이터와 참조형 데이터

```javascript
let x = "cv";
let y = x;

y = "30";

console.log(x); // "cv"
console.log(y); // "30"
```
```
const를 했다면 재할당 받을 일이 없어서 걱정은 없었겠지만, let이기에 설명이 가능한 예제이다.
위는 x가 기본형 데이터, y가 참조형 데이터, 그리고 메모리할당 방식에 차이가 있기에 데이터 값이 다르다. 
참조형은 기본형의 메모리에서 가져온 값이지만, 기본형은 가져올 메모리가 없기에 자신이 가지고 있는 데이터 값을 
메모리에 대입을 한다. 
그래서 x의 값에 담긴 데이터 공간은 "cv"로 유지된채로 y의 값에 담긴 데이터 공간만 바뀌기 때문이라 y만 바뀐 것이다.
이러한 할당과정으로 "자바스크립트의 기본형은 대입할 때의 값을 복사한다"라는 것을 알 수 있다.
```

#### ❓ 호이스팅과 TDZ는 무엇일까?

```
💡 호이스팅(hoisting) : 인터프리터가 변수와 함수의 메모리 공간을 선언 전, 미리 할당하는 것을 말한다. 
아주 가까운 예제로 변수 타입인 var, let const를 들 수 있는데, var로 선언한 변수는 호이스팅 시 
undefined로 초기화하지만, let, const는 초기화를 하지 않는다.
```
```
💡 TDZ(Temporal Dead Zone) : 일시적으로 특정 변수에 접근할 수 없는 구간을 의미한다. 
호이스팅와 관계가 있는 에러이다. 
var같은 경우는 아무런 문제가 없지만, let은 호이스팅이 되지 않는다면 초기화가 안되어 접근하지 못한다.
아래는 TDZ 예시이다.
```
```javascript
// TDZ
console.log(temp); // ReferenceError: Cannot access 'temp' before initialization
// TDZ
let temp = 0;
{
    // TDZ
	console.log(temp); // ReferenceError: Cannot access 'temp' before initialization
    // TDZ
    let temp = 5;
}
```

``` javascript
1 == "1";
1 === "1";
```

위 문제는 숫자 데이터도 문자열 데이터로 바뀔 수 있다는 점을 보여주는 부분이다. '==' 기호는 데이터만 같으면 true를 출력하고, '===' 기호는 데이터, 타입까지 모두 같아야 true를 출력한다. b가 false를 받았기에 "1"은 숫자형이 아니라는 것을 알 수 있다.

내 풀이는 아래와 같다.

```javascript
// 1 == "1"
const a = Boolean(1 == "1");
// 1 === "1"
const b = Boolean(1 === "1");

/* a는 데이터만 같다면 ture를 보내지만, b는 타입마저 같아야 하기에 오른쪽 항에 있는 1은 String이기에 false를 보낸다. */
console.log(a, b); // a = ture, b = false
```
